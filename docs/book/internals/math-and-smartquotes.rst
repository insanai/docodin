.. _math-and-smartquotes:

=====================
Math and smart quotes
=====================

Two parts of docutils are text-processing libraries in their own right: the math
converters that turn LaTeX math into HTML or MathML, and SmartyPants, which educates
quotes, dashes and ellipses.  docodin ports both to Odin, with docutils' output character
for character.

Math: odin/math
===============

The package ``texmath`` converts LaTeX math like ``docutils.utils.math`` in docutils
0.22.4:

``math2html``
   TeX to HTML with the classes of ``math.css`` (docutils' ``math2html``, which comes
   from eLyXer's formula converter).  A formula is translated in three passes, as in
   docutils: **parse** (a cursor over the source with a stack of endings feeds the bit
   kinds and command kinds, which build a tree of nodes), **process** (scripts become
   limits and stacks, ``\left`` and ``\right`` brackets are resized, letters set in
   italics) and **output** (each node writes its HTML into one builder).
``tex2mathml``
   TeX to presentational MathML (docutils' ``latex2mathml``).  The parser walks the
   source and keeps an insertion point in the element tree; commands are handled in
   ``l2m_commands.odin``.
``uni2tex``, ``uni2tex_translate``
   The ``unichar2tex`` table of the LaTeX writer; the ``tex2unichar`` dictionaries are
   the ``TEX2UNICHAR_*`` tables.

Errors are docutils' errors.  Problems in the input are reported as docutils reports them
(``Trace.error`` lines on standard error, collected in the result's ``trace``).  Where
docutils raises an exception, a ``MathError`` for invalid input or an ``AttributeError``,
``IndexError`` or other Python error that some input provokes in docutils, the
conversion stops at the same point and returns an ``Exception`` with the Python
exception's type and message.  Nesting is limited to ``MAX_DEPTH`` (1000) levels; deeper
input raises ``RecursionError``, as docutils does (docutils already stops at about 190
nested groups in ``math2html`` with Python's default recursion limit).

The command tables (``*_tables.odin``) are generated from docutils by
``scripts/gen_math_tables.py``.  The HTML5 writer uses the converters for
``math_output`` ``HTML`` and ``MathML``, and the LaTeX writer uses ``uni2tex``.

``tests/native_math_differential.py`` generates random TeX from a small grammar (groups,
templates, environments, scripts, and the commands docutils knows) and compares the
output, the trace messages and the exceptions with docutils.

Smart quotes: odin/text
=======================

``educate_tokens`` is a port of ``docutils.utils.smartquotes`` that reproduces its output
character for character, including the quirks of its regular expressions:

- Every rule of the original is a ``str.replace`` or a ``re.sub`` whose match contains an
  ASCII quote character.  The rules run as separate passes, each over the output of the
  previous one, exactly as in the original: text that one rule inserts (for example the
  no-break space of French quotes) is seen by the following rules.
- A regex rule is reproduced by a scanner that visits the quote characters and tests the
  context that the pattern's groups and look-arounds would see.  A pass with nothing to
  do returns its input.
- Tokens are ``tag``, ``literal`` or text, as in docutils; every language and every
  attribute mode is supported, and customised quotes (``smartquotes_locales``).

The quote tables are generated by ``scripts/gen_smartquotes_tables.py``.  In Python, the
``SmartQuotes`` transform of docodin's docutils package calls ``docodin_educate`` when the
library is available, with one traversal of the document and cached language data; the
Python implementation stays as the reference and the fallback.  The native transforms
use ``educate_tokens`` directly.

``tests/smartquotes_differential.py`` educates random token sequences (text, literal and
tag tokens made of quotes, dashes, dots, backslashes, letters, digits, Unicode
punctuation and white space) with random attribute modes and languages, and with
customised quotes, natively and in Python; the results must be identical.
