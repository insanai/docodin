docodin **1.0.0b1** is the first public beta of a native reStructuredText toolchain written in Odin. It includes standalone publishing, documentation sites and PDF books, an editor language server, and Python integration for docutils and Sphinx.

### Install

Use Python **3.12 or later** on a supported platform:

```sh
pip install docodin==1.0.0b1
# Include Sphinx support:
pip install 'docodin[sphinx]==1.0.0b1'
```

The wheel installs `docodin`, `docodin-check`, `docodin-lsp`, the native library and the Python package. Supported native documents can also be processed without Python using the native archives below.

### What's included

- **Native publishing:** HTML5, LaTeX, XeLaTeX, Docutils XML and pseudo-XML, with docutils-compatible diagnostics and exit status within the documented support contract.
- **Documentation sites and books:** a native HTML theme with light/dark modes, navigation, search and cross-document references; PDF books compiled with an external TeX engine.
- **Markup checks and editor tools:** source excerpts and hints from `docodin-check`; diagnostics, quick fixes, definitions, references, hover, completion, symbols, folding and semantic tokens from `docodin-lsp` within a document.
- **Python and Sphinx integration:** direct native publishing, the docutils shim, `docodin-sphinx-build`, `DOCODIN_DOCUTILS=1` and the `docodin.sphinx` parser extension.
- **Native image metadata:** PNG, JPEG, GIF, BMP, TIFF and WebP dimensions without Pillow or pixel decoding; unsupported cases retain the Python fallback.
- **Inline Graphviz diagrams:** architecture, parser fallback, data storage, publishing pipeline, language-server message flow, DOD lifecycle and release process. Native HTML supports separate light/dark palettes for adaptive diagrams; PDFs contain light vector diagrams.
- **Downloadable documentation:** the complete manual, collected design records and **19 individual DOD PDFs**, all in a print-friendly light layout. DOD 1 uses a DOT state-transition graph.

### Fixes in this beta

- Full paths to LuaLaTeX and XeLaTeX preserve Unicode just like bare engine names.
- Chapter-local contents remain aligned after an unnumbered opening chapter.
- PDF subprocesses inherit TeX environment and font settings. The PDF theme preserves nested inline roles on older supported LaTeX installations.
- Concurrent LaTeX writers initialize their preamble cache once.
- Retired threads no longer retain shared-library arena blocks: the process-wide cache is bounded to eight blocks of at most 4 MiB each.
- Unreadable or non-UTF-8 book sources stop the build with a diagnostic rather than producing invalid output.
- Patched docutils parser grammars and `DOCODIN_NATIVE=0` select the Python parser; see the import-order caveat below.

### Requirements and beta limits

- PDF generation needs **TeX Live or MacTeX**; inline DOT rendering needs **Graphviz**. These tools are not bundled. Python-dependent features use the Python fallback.
- The verified binary platforms are Linux x86-64 with glibc 2.34+ and macOS arm64. Windows, musl Linux and other architectures are not verified for this beta.
- **Complete compatibility with every Sphinx project and extension is outside this beta's promise.** Native book builds read the documented `conf.py` values without executing Python or loading Sphinx extensions. Native inline Graphviz supports the documented directive subset; Sphinx's extension supports its full options.
- For the parser integration with an installed stock docutils, import `docodin.parser` before extensions patch parser states. `DOCODIN_NATIVE=0` explicitly selects Python parsing.
- The language server works on one document at a time and has no rename or cross-document index. Collector tuning is opt-in and can change results with duplicate labels.
- Faster parsing does not imply the same improvement for a complete Sphinx build. Published benchmarks distinguish native site builds from replacing the parser inside Sphinx; this beta does not promise a universal speed-up.

Review the [known limits](https://insanai.github.io/docodin/book/reference/limits.html) and compare your project's output before production adoption. Report reproducible problems through [GitHub Issues](https://github.com/insanai/docodin/issues).

### Validation and integrity

Release qualification runs Odin and Python tests, builds a wheel from the source distribution, installs it outside the checkout and checks the native programs, Python API, Sphinx integration and documentation. Linux qualification produces all 21 documentation PDFs; `auditwheel` checks the Linux wheel's platform requirements. GitHub and PyPI use the same qualified wheels and source distribution.

Verify downloads with [SHA256SUMS](https://github.com/insanai/docodin/releases/download/v1.0.0b1/SHA256SUMS). [RELEASE.json](https://github.com/insanai/docodin/releases/download/v1.0.0b1/RELEASE.json) records the tested revision, version and artifact hashes. See the [full changelog](https://github.com/insanai/docodin/blob/v1.0.0b1/CHANGELOG.rst) for implementation details.
